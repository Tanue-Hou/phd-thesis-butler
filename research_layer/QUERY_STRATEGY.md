# Стратегия построения поисковых запросов для систематического обзора

## 1. Декомпозиция темы исследования на русскоязычные ключевые слова

### 1.1. Принцип декомпозиции

Тема диссертации разбивается на **2-4 концептуальных блока**, каждый из которых представляется набором ключевых терминов. Блоки комбинируются логическим оператором И (AND).

**Алгоритм:**
1. Выделить из формулировки темы существительные и устойчивые словосочетания, обозначающие концепты
2. Для каждого концепта составить список синонимов, родовых и видовых терминов
3. Уточнить терминологию: проверить, какие формулировки реально используются в российских научных публикациях (по выборке из eLIBRARY)
4. Исключить термины, дающие избыточный шум (слишком общие: «метод», «исследование», «анализ»)

**Пример декомпозиции (гипотетическая тема «Цифровая трансформация управления человеческими ресурсами в промышленных организациях»):**

| Блок | Концепт | Ключевые термины |
|------|---------|------------------|
| A | Цифровая трансформация | цифровая трансформация, цифровизация, Industry 4.0, Индустрия 4.0, smart-организация |
| B | Управление человеческими ресурсами | HRM, управление персоналом, человеческие ресурсы, кадровый менеджмент, HR-менеджмент |
| C | Промышленные организации | промышленное предприятие, производственная организация,制造业, промышленность, индустрия |

### 1.2. Метод верификации терминов

Для каждого блока:
1. Ввести термин в поиск eLIBRARY — оценить число результатов (>50 — термин продуктивен)
2. Проверить первые 10 результатов на релевантность (>50% релевантных — термин точен)
3. Из аннотаций релевантных статей извлечь дополнительные синонимы
4. Повторить для каждого нового синонима

## 2. Расширение синонимов и близких терминов

### 2.1. Типы расширения

| Тип | Описание | Пример |
|-----|----------|--------|
| Синонимы | Разные обозначения одного понятия | «управление персоналом» = «HRM» = «HR-менеджмент» |
| Родовые термины | Более широкое понятие | «цифровизация» → «информационные технологии» |
| Видовые термины | Более узкое понятие | «цифровая трансформация» → «внедрение ERP-систем» |
| Англоязычные эквиваленты | Термины из англоязычной литературы | «цифровая трансформация» = «digital transformation» |
| Варианты написания | Слитно/раздельно, с дефисом, транслитерация | «e-learning» = «электронное обучение» = «дистанционное обучение» |

### 2.2. Источники синонимов

- Аннотации релевантных статей (ключевые слова авторов)
- Статьи-обзоры по теме (обычно содержат терминологическую справку)
- Словари и энциклопедии (в т.ч. Википедия на русском языке для начального ориентира)
- Thesaurus / предметные рубрики журналов

### 2.3. Контроль качества

- Слишком широкие синонимы (дающие >10 000 результатов без фильтров) — исключить или уточнить
- Слишком узкие синонимы (дающие <5 результатов) — использовать в дополнительных проходах, но не в основном запросе
- Англоязычные термины использовать для eLIBRARY (индексирует часть англоязычных публикаций) и CyberLeninka; для DisserCat — только русские

## 3. Соответствие кодам специальностей ВАК

### 3.1. Зачем это нужно

Специальность ВАК (Высшей аттестационной комиссии) — обязательный атрибут диссертации. Поиск по коду специальности:
- Резко сужает выдачу до релевантной области
- Позволяет найти диссертации, в названии которых не используются ваши ключевые слова
- Обеспечивает полноту: все диссертации по специальности так или иначе связаны с вашей темой

### 3.2. Как определить релевантные специальности

1. Посмотреть, по каким специальностям защищались ближайшие аналоги вашего исследования (в DisserCat)
2. Проверить перечень специальностей ВАК (актуальная редакция): https://vak.minobrnauki.gov.ru
3. Для междисциплинарных тем — выбрать 2-3 смежных специальности

**Примеры кодов (для гуманитарных и управленческих наук):**

| Код | Наименование | Применимость |
|-----|-------------|--------------|
| 08.00.05 | Экономика и управление народным хозяйством | Широкий профиль, подходит для управленческих тем |
| 08.00.01 | Экономическая теория | Для теоретических аспектов |
| 05.13.01 | Системный анализ, управление и обработка информации | Для цифровых/информационных аспектов |
| 22.00.04 | Социальная структура, социальные институты и процессы | Для социальных аспектов HR |

### 3.3. Использование в запросах

```
# eLIBRARY: поле "Специальность" в расширенном поиске
Специальность ВАК: 08.00.05

# DisserCat: фильтр по специальности в каталоге
Фильтр → Специальность → 08.00.05
```

## 4. Конструирование поисковых запросов

### 4.1. Для eLIBRARY

eLIBRARY поддерживает булеву логику в полнотекстовом поиске.

**Структура запроса:**
```
(Блок_A_термин1 OR Блок_A_термин2) AND (Блок_B_термин1 OR Блок_B_термин2) AND (Блок_C_термин1 OR Блок_C_термин2)
```

**Практический пример:**
```
("цифровая трансформация" OR "цифровизация" OR "Industry 4.0") AND ("управление персоналом" OR "HRM" OR "человеческие ресурсы") AND ("промышленное предприятие" OR "промышленная организация")
```

**Дополнительные ограничения (через фильтры веб-интерфейса):**
- Год: 2021-2026 (последние 5 лет)
- Тип публикации: Статья
- Специальность ВАК: 08.00.05 (если применимо)

**Стратегия перебора:**
1. Полный запрос (все 3 блока) — точный, но может пропустить
2. Запрос из 2 блоков (A+B, A+C, B+C) — шире, больше шума
3. По одному блоку + специальность ВАК — для обнаружения неожиданных пересечений

### 4.2. Для DisserCat

DisserCat имеет ограниченный поиск (по одному полю или общий полнотекстовый). Стратегия отличается:

**Алгоритм:**
1. Поиск по ключевым словам блока A: `цифровая трансформация`
2. Фильтр: специальность ВАК 08.00.05, тип — кандидатская/докторская, год — 2021-2026
3. Просмотреть результаты, отобрать релевантные
4. Повторить для блока B и блока C
5. Пересечения (диссертации, найденные по нескольким блокам) — приоритетные

**Конкретные запросы:**
```
# Запрос 1: Основной термин + специальность
"цифровая трансформация" + фильтр: 08.00.05, 2021-2026

# Запрос 2: Синоним + специальность
"цифровизация управления" + фильтр: 08.00.05, 2021-2026

# Запрос 3: Англоязычный термин (если есть в названиях)
"digital transformation" + фильтр: 08.00.05, 2021-2026
```

### 4.3. Для CyberLeninka

```python
# API-запрос (псевдокод)
params = {
    "q": "цифровая трансформация управление персоналом",
    "page": 1,
    "size": 50
}
response = requests.get("https://cyberleninka.ru/api/search", params=params)
```

**Стратегия:**
1. Запрос по двум основным блокам (A+B)
2. Ограничение по году через постфильтрацию результатов
3. Для найденных статей — загрузка полного текста и извлечение ссылок (для расширения базы)

## 5. Ограничение временного диапазона (5 лет)

### 5.1. Обоснование

Пятилетний период (2021-2026) обеспечивает:
- Актуальность: включает все публикации после пандемии COVID-19 (ускорившей цифровизацию)
- Полноту: достаточный массив для выявления тенденций
- Управляемость: ограничивает объём выдачи до обрабатываемого

### 5.2. Реализация в каждом источнике

| Источник | Метод ограничения |
|----------|-------------------|
| eLIBRARY | Фильтр «Год» в расширенном поиске: с 2021 по 2026 |
| DisserCat | Фильтр «Год защиты»: с 2021 по 2026 |
| CyberLeninka | Постфильтрация результатов API по полю `year` |
| RSL/НЭБ | Фильтр «Год» в расширенном поиске: с 2021 по 2026 |

### 5.3. Расширение при необходимости

Если пятилетний диапазон даёт <20 релевантных источников:
- Расширить до 10 лет (2016-2026)
- Снизить требования к релевантности (включить смежные темы)
- Добавить англоязычные базы (Scopus, WoS) — но это выходит за рамки данного профиля

## 6. Оценка качества и релевантности результатов

### 6.1. Критерии релевантности

Каждый найденный документ оценивается по трёхбалльной шкале:

| Балл | Категория | Критерий |
|------|-----------|----------|
| 2 | Высокая | Непосредственно по теме исследования; методология, объект или проблематика совпадают |
| 1 | Средняя | Смежная тема; содержит полезный теоретический или методологический материал |
| 0 | Низкая | Не связана с темой; терминологическое совпадение случайное |

### 6.2. Критерии качества источника

| Критерий | Проверка |
|----------|----------|
| Рецензируемость | Входит ли журнал в перечень ВАК / Scopus / WoS? |
| Индексация | Есть ли запись в РИНЦ? Какой импакт-фактор? |
| Авторитетность автора | Число публикаций, h-индекс, принадлежность к известной школе |
| Методологическая строгость | Наличие чёткой методологии, эмпирической базы, статистического анализа |
| Актуальность ссылок | Список литературы включает источники не старше 5-7 лет? |
| Объём и структура | Для статей — не менее 10 страниц; для диссертаций — полная структура (введение, главы, заключение) |

### 6.3. Практический алгоритм фильтрации

```
Шаг 1: Быстрая оценка (по аннотации)
  - Релевантность >= 1? → ДА: перейти к шагу 2 / НЕТ: отклонить

Шаг 2: Оценка качества (по метаданным)
  - Журнал в перечне ВАК? ИЛИ цитирования > 5 (РИНЦ)? ИЛИ журнал в Scopus?
  - ДА: перейти к шагу 3 / НЕТ: пометить как «низкое качество», но не отклонять

Шаг 3: Глубокая оценка (по полному тексту / автореферату)
  - Релевантность == 2? → Включить в основную выборку
  - Релевантность == 1? → Включить в дополнительную выборку
  - Релевантность == 0? → Отклонить (ложное срабатывание поиска)

Шаг 4: Дедупликация
  - Совпадение по DOI, названию (>80% совпадение строк), или автор+год+журнал
  - При дублировании: приоритет CyberLeninka (полный текст) > eLIBRARY (метаданные + цитирования) > DisserCat (автореферат) > RSL (полный текст диссертации)
```

### 6.4. Пороговые значения для включения в обзор

- **Минимальный размер выборки:** 30 источников (статьи + диссертации)
- **Оптимальный размер:** 50-80 источников
- **Доля высокорелевантных (балл 2):** не менее 40% от общего числа
- **Доля диссертаций:** 10-20% (для демонстрации охвата диссертационных исследований)
- **Доля источников с открытым полным текстом:** не менее 50% (CyberLeninka + открытые диссертации RSL)

## 8. Документирование процесса

Каждый поисковый сеанс фиксируется в журнале:
- Дата и время
- Источник (eLIBRARY / DisserCat / CyberLeninka / RSL)
- Текст запроса
- Число результатов
- Число отобранных (релевантных) результатов
- Примечания (особенности выдачи, ошибки, CAPTCHA)

Журнал ведётся в файле `research_layer/search_log.md`.
